# CH582M 全外设引脚语义普查（2026-10-07）

方法：以本地 `CH583DS1 V1.9` 为唯一事实来源，逐外设核对三类问题：**① 整组映射约束 ② 信号子集/模式（腾脚）语义 ③ 未建模的引脚占用机制**。

## 结论总表

| 外设 | 检查项 | 结论 | 处理 |
|---|---|---|---|
| SPI0 | 整组映射（RB_PIN_SPI0） | 一位切 4 根，不可混搭 | ✅ 已建模 |
| SPI0 | 模式/腾脚（表7-3） | 半双工：**MOSI「未用到，可做通用 I/O」**；全双工：MISO 为官方定义输入，不可复用 | ✅ 已建模（full/half 两模式）；"仅发送省MISO"已删除 |
| SPI0 | **从机模式**（需 SCS 脚、SCK 转输入） | 手册支持，工具未建模 | 📋 评估项 |
| UART0-3 | 整组映射 | 一位一组，已建模 | ✅ |
| UART0-3 | "只发/只收腾脚" | 手册**无任何**"未用到/可做通用"字样 → 不可腾（两脚都占） | ✅ 保守建模正确 |
| UART0 | **MODEM 信号**（RTS/CTS/DTR/DSR/RI/DCD，默认 PB6/PB0/PB5/PB1/PB2/PB3；DSR_/DTR_ 可整组映射到 PB14/PB15） | 未建模（属"可选信号"，需要信号可选性模型） | 📋 评估项 |
| I2C | 两线必需 + 映射位 | 无子集语义 | ✅ |
| TMR0-3 | 各独立映射位（单信号两落点） | 已建模为信号级二选一 | ✅ |
| **PWM4/5/7/8/9** | **RB_PIN_PWMX：一位切 5 通道** | **模型缺陷：此前允许 5 通道分开选组（硬件做不到）** | ✅ **本轮修复**（groupKey 共享映射位约束） |
| PWM6/10/11 | 无映射位、单脚 | ✅ |
| USB1/USB2 | RB_PIN_USB_IE / RB_PIN_USB2_IE 引脚使能位（默认关）；两线整组 | 与"未分配=未使能"的资源模型等价 | ✅ 模型等价，无需改 |
| ADC/TKEY | 单脚；R16_PIN_ANALOG_IE 数字输入禁用位（省电向，非占用语义） | ✅ |
| 系统 | 调试口 PB14/15、RST PB23、32K 晶振 PA10/11 | ✅ 已建模为全局开关 |
| 系统 | **RB_RF_ANT_SW_EN：RF 天线开关输出到 PB[16]~PB[21]** | 手册仅此一句，具体占几根/如何分配无说明 | 📋 评估项（若用 BLE 天线开关再查 RF 应用资料） |

## 关键原文摘录

- 表7-3 SPIx：`MOSIx 半双工模式-主模式 未用到，可做通用I/O`；`MISOx 全双工模式-主模式 输入（浮空输入/上拉输入/下拉输入）`
- RB_PIN_PWMX：`1：PWM4/5/7/8/9映射到 PA[6]/PA[7]/PB[1]/PB[2]/PB[3]；0：…PA[12]/PA[13]/PB[4]/PB[6]/PB[7]`
- §7.3.1：`上电后默认所有 I/O引脚均为通用 I/O功能，启用各功能模块后，相应的原 GPIO引脚被配置成各自功能模块对应的功能引脚`；多抢占按引脚表优先级（GPIO 最低）
- RB_PIN_USB_IE / RB_PIN_USB2_IE：`1：PB10-11（PB12-13）为USB通讯引脚；0：不用于USB通讯`（默认 0）

## 评估项（后续按需立项，不动工）

1. **optional signals（可选信号）模型**：UART0 MODEM 六个信号各自可选；也可支撑未来其他芯片的"任意子集"场景。
2. **SPI 从机模式**：作为 SPI0 的第三个模式（含 SCS 信号与 SCK 输入语义）。
3. **RF 天线开关（PB16-21）**：语义需补查 RF 资料后再定建模方式。
4. **多芯片/多封装结构演进**（用户提醒，单独评估）：
   - 现状已是"通用引擎 + 每芯片数据文件"，新增芯片 = 新增 `chips/*.js`，引擎零改动；封装三族参数化渲染。
   - 待评估：多芯片选择 UI（registry 已支持推入多文件，UI 当前取 [0]）；BGA/custom 封装逃生舱落地；schema 版本迁移策略。

## 2026-10-07 BUG 猎杀与数据交叉验证记录

1. **模糊测试**（`node tests/fuzz.js`）：8000 次随机操作（分配/解除/开关/GPIO/模式切换/随机非法分配），每次全量不变量断言（分配结构合法、IO 守恒 40、claims 引脚合法、groupKey 同键同侧、双占必标冲突、导出往返一致）＋撤销 50 连击回初始＋不可变性 —— **全部通过**。
2. **手册对账（双引擎）**：pypdf 全文 vs pdfplumber 二次抽取，40 个 IO 引脚复用功能表 **100% 一致**。实测 pdfplumber 会吞掉"1：…映射到"短语段（PWMX/SPI0 位描述处）→ **单引擎不可信赖**，本数据以"逐脚引脚表 + 表7-7 重映射表 + 寄存器位描述"三处冗余互证为准。
3. **发现的手册自身瑕疵（非数据错误）**：① pin40(PA1)、pin41(PA2) 的功能描述误写成以"PA0："开头（两处笔误块与我们的数据反向核对完全吻合）；② RB_PIN_SPI0 位描述的名称顺序（SCK0 在前）与表7-7（SCS 在前）不一致——表7-7 与逐脚引脚表定位一致，数据取后者。
4. **CH585/CH584 官方手册（159 页，2024）跨代惯例佐证**：半双工 MOSI"未用到，可做通用I/O"、RB_TMR_MODE_IN 语义、SPI0 映射句式在两代文档中一致。
5. **本轮唯一修复项**：共享映射位（PWMx）切换被拒时补充解套提示"可先解除 X 再切换"（真实鼠标实测解套路径通过）。
6. 工具固化：`tools/pdf-crosscheck.py`（未来新芯片数据审计模板）；`tests/fuzz.js`（常驻不变量测试）。
